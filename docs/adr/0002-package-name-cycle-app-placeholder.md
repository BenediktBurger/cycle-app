# ADR-0002: Package name `cycle_app` is a placeholder

- **Date:** 2026-09-15
- **Status:** Accepted

## Context

The project needs a Dart package name for `pubspec.yaml`, for
`flutter create --project-name …`, localization generation and imports. A
final product name (bundle IDs, display name, package path) has not been
chosen, and choosing one now would cause renames across Android/iOS bundle
identifiers, store listings, and the app display name later.

## Decision

Use **`cycle_app`** as the package name for now and mark it explicitly as a
**PLACEHOLDER** (documented in the README and pubspec). Everything is coded
against this name consistently.

Placeholder placement: a rename is a single `pubspec.yaml` `name:` change plus
re-running `flutter create`, since imports reference `package:cycle_app/…`
only inside this repo.

## Consequences

- All code, tests, and CI use `cycle_app` consistently, so a later rename
  stays trivial: one pubspec change + `flutter create` rerun + a mechanical
  `package:cycle_app/…` import update.
- The *display name* (what the user sees) is localized in the ARB files and is
  a natural-language placeholder vs. a real product name — it can be changed
  independently of the package name.
- Bundle identifiers/platform folders generated by `flutter create` will
  default to the placeholder name; a real product name will require
  regenerating or editing platform manifests when it is chosen.
- README and docs must keep flagging the name as a placeholder to prevent
  accidental adoption of the placeholder as the actual product name.
