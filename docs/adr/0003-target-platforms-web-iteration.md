# ADR-0003: Web/Chrome as iteration target; Android + iOS as product targets

- **Date:** 2026-09-15
- **Status:** Accepted

## Context

The product is a mobile app for **Android + iOS**. During development, though,
we need a fast iteration/test loop (start app, add data, inspect behavior)
without depending on Android Studio/Xcode toolchains or emulators. Flutter web
running in Chrome gives exactly that for this app's needs, with a much lighter
toolchain. Additionally, a PWA is a cheap bonus later.

Platform constraints: some Flutter packages are Android-only or
otherwise native-only. Using such packages in code shared across platforms
would break the web iteration loop, or force plugin Availability checks
everywhere.

## Decision

- The **product targets Android + iOS**. A PWA is a welcome bonus.
- **Web/Chrome is the iteration and test target** during development; CI also
  builds for web (`flutter build web`) as the lightest compile check.
- **No Android-only plugins in core code.** Any dependency that does not work
  on web must be isolated behind platform-guarded conditional imports, or
  confined to a clearly separated feature layer — never imported from core
  UI/domain code.
- Platform folders for Android/iOS are generated by the user locally
  (`flutter create --platforms=android,ios …`, see CONTRIBUTING.md); the web
  shell (`web/index.html`, `web/manifest.json`) is hand-written and kept
  minimal.

## Consequences

- Fast local iteration (`flutter run -d chrome`) without a mobile toolchain;
  CI's first real compile check is a web build, which is cheap and stable.
- Package selection is constrained: dependencies must work on web (or be
  cleanly isolated). Examples honored in other ADRs: drift uses
  `WasmDatabase` on web; `flutter_secure_storage` (native later) and
  `sqlcipher_flutter_libs` (native later) must never leak into shared code —
  web gets a PIN lock only (see ADR-0005).
- The web iteration path requires drift's `sqlite3.wasm` + worker assets to be
  available for the web build (documented separately when the DB lands).
- Platform feature parity is asymmetric: features that work only on native
  (SQLCipher, biometric lock) are "optional/native-later" by design, not
  regressions of web.

## Update 2026-09-21: native encryption split superseded

The native-encryption asymmetry described above is historic: native at-rest
encryption landed pre-release via SQLite3MultipleCiphers (not SQLCipher, no
`sqlcipher_flutter_libs`), always-on with no settings toggle — see the
amendment in [ADR-0005](0005-storage-and-encryption.md). The platform
iteration decisions here (web as test target, no native-only plugins in
core code, cheap CI web build) are unaffected. Web storage stays
unencrypted, as decided.

## Update 2026-09-28: public web demo on GitHub Pages is a bonus, not a promotion

The web build now runs as a public demo at
[github.io/cycle-app](https://BenediktBurger.github.io/cycle-app/)
(see [ADR-0012](0012-public-web-demo-github-pages.md)). This is exactly the
"PWA is a welcome bonus" of the decision above: web remains the **iteration
target**, Android + iOS remain the **product targets** — the demo does not
change that.

## Amendment 2026-10-20: web is a supported secondary target

**Status: Accepted (amends the platform-target decision above; the iteration
and test role, the no-native-only-plugins rule, and the cheap CI web build are
unchanged).** The original text above is kept for the record; where it
conflicts with this amendment, the amendment governs.

The web build has left the "welcome bonus" status: it is a **supported
secondary target**, served publicly (ADR-0012) and installable as a PWA.

Supported: data entry, statistics, the cycle view, PDF, JSON export/import,
and the installed PWA. Not guaranteed: Safari-tab durability, at-rest
encryption, sync, raw database-file copy, and background notifications.

- **The installed PWA is the durable web mode.** A normal Safari tab is not
  guaranteed to retain data: WebKit evicts script-writable storage after
  seven days of Safari use without interacting with the site. Onboarding and
  the README state the durability rule before real data is entered; the
  shell's iOS install hint repeats it, and the Settings storage card reports
  the live install and persistence state.
- **Android and iOS remain the primary targets.** They are the reference
  feature set; web parity covers the contract above, not every native
  capability. Native at-rest encryption stays native-only and always-on
  ([ADR-0005](0005-storage-and-encryption.md)); web storage stays
  unencrypted.
- **Web remains the iteration and test target.** `flutter run -d chrome` and
  CI's `flutter build web` stay the cheap inner loop and first compile check,
  and the no-native-only-plugins rule still constrains package selection.
- This amendment promotes an existing target's status; it adds no third
  product platform and no new platform decision.
